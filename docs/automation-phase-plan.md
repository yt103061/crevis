# 自動化ロードマップ提案（Phase 1.5 / 2 / 3）

最終更新: 2026-02-23

## 背景
現状は以下の状態です。

- ニュースレター
  - RSS収集 + AI要約処理は実装済み（管理画面ボタン起点）
  - 記事承認は手動
  - 号作成は手動トリガー
  - 配信は手動実行
- LP
  - URL手入力で登録し、AI分析とスクリーンショットを実行
  - 自動収集パイプラインは未実装

本ドキュメントでは、次に進めるべき実装を 3 段階で提案する。

---

## 1) ニュースレター完全自動化（記事承認〜号作成〜配信）

### Phase 1.5（半自動化）
**目的:** 人のレビューは残しつつ、定常作業を80%削減する。

- 機能
  1. **定時収集ジョブ化**（cron）
     - `/api/admin/nl/fetch` 相当をバッチ化
     - 1日 2〜4 回実行（朝・昼・夕）
  2. **AI一次判定（承認候補）**
     - `relevance_score` の閾値で `approved_candidate` を自動付与
     - 重複ソース / 類似タイトル / 低品質記事を自動除外
  3. **号ドラフト自動生成（下書きまで）**
     - 週次で `newsletter_issues` の draft を自動作成
     - 上位記事を自動で `featured_articles` にセット
  4. **配信前チェックリストUI**
     - タイトル、記事件数、禁則語、リンク切れの最終確認

- 運用
  - 編集者は「候補確認 → 必要な差し替え → 配信ボタン」のみ

- KPI
  - 1号あたり作業時間: **60分 → 15分以内**
  - 記事収集漏れ率: **20% → 5%以下**

- 完了条件（DoD）
  - 週次で自動下書きが生成される
  - 管理画面で候補承認が可能
  - 手動配信で正常送信できる

### Phase 2（条件付き全自動）
**目的:** 品質ガードを入れたうえで、原則無人配信に移行する。

- 機能
  1. **自動承認ルールエンジン**
     - スコア閾値 + ソース信頼度 + 鮮度 + 重複率で承認判定
  2. **自動号作成テンプレート強化**
     - 「今週の要点3つ」「実務アクション」「参考リンク」等を自動構成
  3. **自動配信スケジューラ**
     - 木曜 8:00 など固定時刻で send
     - 失敗時は再送キューへ
  4. **配信ガードレール**
     - 最小記事数、最大同一ソース比率、エラー率閾値で自動停止
     - 自動停止時は Slack / Email 通知

- KPI
  - 自動配信率: **70%以上**
  - 誤配信率: **0.5%以下**
  - 開封率/クリック率の週次可視化

- 完了条件（DoD）
  - 指定条件を満たす号は無人で配信される
  - 異常時に自動停止し通知される

### Phase 3（最適化・自己改善）
**目的:** 配信成果に応じて、内容選定と配信戦略を継続改善する。

- 機能
  1. **パーソナライズ配信**
     - 業界 / 関心タグ / 過去クリックで記事優先度を変える
  2. **件名・本文A/Bテスト**
     - 件名、導入文、CTA文言の自動実験
  3. **学習ループ**
     - クリック/滞在/解除を評価し、次号の選定重みへ反映
  4. **配信時間最適化**
     - セグメントごとの最適送信時刻に分散配信

- KPI
  - CTR: **Phase 1.5比 +20%**
  - 解除率: **Phase 2比 -15%**
  - 編集工数: **ほぼ監視のみ（5分/号以下）**

## 2) LP自動収集

### Phase 1.5（収集基盤）
**目的:** 手動登録中心から、候補収集中心へ移行する。

- 機能
  1. **収集ソース管理**
     - 広告ライブラリ、業界メディア、検索クエリ等の source 定義
  2. **クローラ / フェッチャ実装**
     - URL正規化、重複除外、robots遵守、レート制御
  3. **LP候補テーブル追加**（例: `lp_candidates`）
     - `url`, `source`, `fetched_at`, `status(new/reviewed/accepted/rejected)`
  4. **候補レビューUI**
     - サムネ/タイトル/ドメイン単位で一括承認

- KPI
  - 週次新規候補: **100件以上**
  - 重複率: **30%以下**

- 完了条件（DoD）
  - 毎日自動で候補が蓄積される
  - 管理画面から承認して既存LP登録フローに接続できる

### Phase 2（自動登録 + 品質評価）
**目的:** 承認待ちを減らし、一定品質以上を自動登録する。

- 機能
  1. **LP判定モデル**
     - 「LPらしさ」スコア（単一CTA、縦長構造、フォーム有無など）
  2. **自動カテゴリ推定**
     - 業界、目的、訴求タイプをAIで付与
  3. **自動登録ルール**
     - 高信頼ソース + LPらしさ高 + 重複なし = 自動 `lps` 登録
  4. **スクショ/分析ジョブの非同期キュー化**
     - 失敗リトライ、タイムアウト管理、優先度制御

- KPI
  - 自動登録率: **40%以上**
  - 誤登録率: **2%以下**
  - 登録から公開までの時間: **24h → 2h以内**

- 完了条件（DoD）
  - 収集→判定→登録→分析→公開まで非同期で接続
  - 品質閾値未満は自動でレビュー待ちへ分岐

### Phase 3（スケール + 収益化連携）
**目的:** 競争優位となる収集網とデータ資産化を実現する。

- 機能
  1. **業界別クローリング戦略最適化**
     - 業界ごとに高収穫ソースへ自動配分
  2. **変化検知**
     - 同一LPの改修差分を追跡し、時系列で比較可能に
  3. **ランキング/トレンド生成**
     - 週次・月次で「伸びている訴求」「勝ちパターン」提示
  4. **有料機能連携**
     - プロ向けに速報アラート、類似LP推薦、API提供

- KPI
  - 有効LPカバレッジ: **Phase 2比 +2〜3倍**
  - 更新鮮度（新規反映まで）: **6時間以内**
  - 有料転換率向上

## 優先実装順（推奨）
1. **ニュースレター Phase 1.5**（短期で運用工数が最も下がる）
2. **LP自動収集 Phase 1.5**（データ母集団を拡大）
3. ニュースレター Phase 2（条件付き無人化）
4. LP自動収集 Phase 2（自動登録率向上）
5. 両ドメインの Phase 3（最適化/収益化）

## ざっくり期間目安
- Phase 1.5: 2〜4週間
- Phase 2: 4〜8週間
- Phase 3: 8週間〜（運用しながら継続改善）

## 依存関係
- ジョブ基盤（Vercel Cron / GitHub Actions / Supabase Edge Functions いずれか）
- 通知基盤（Slack or Email）
- メトリクス収集（開封/クリック/配信エラー/記事評価）
- 管理画面の状態遷移設計（manual override を常に可能にする）
