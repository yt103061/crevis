## 1. 現在できること（実装済み）

### A. NL（ニュースレター）運用
- **ソース管理**: 管理画面から `nl_sources`（RSS想定）を登録/編集/有効化できる。
- **記事収集 + AI要約**: `/api/admin/nl/fetch` でアクティブソースを巡回し、最新記事を取り込み。重複URLはスキップし、AIで日本語要約・翻訳タイトル・キーポイントを生成して `nl_articles` に保存。
- **承認フロー**: 管理画面で `pending/approved/rejected` を切替可能。
- **号作成・配信**: 号を作成して `draft -> ready -> sent` に進め、Resendで一斉配信できる。

### B. LPギャラリー運用
- **LP登録 + AI分析**: 管理画面からLP URLを登録すると、AI分析（4軸 + 総合点）を実行して `lp_analyses` に保存。
- **公開ページ反映**: トップページは `status='active'` のLPを取得し、分析結果つきで一覧表示。並び替え・フィルタあり。
- **再分析/状態変更**: 管理画面で再分析・アーカイブ化可能。

## 2. 質問への回答（可否判定）

### 2-1. 「海外主要NL + 日本情報源を調べて記事化し、NL配信まで自動」
- **結論**: **部分的に可能（半自動）**。
- 可能な範囲:
  - 海外/国内問わず、RSS URLを `nl_sources` に登録すれば自動収集対象にできる。
  - 収集→AI要約→候補化までは自動。
- 自動化が未完の範囲:
  - 「どのソースを採用するか」の探索・選定は手作業。
  - 記事承認は管理画面で人手操作。
  - 号本文はテンプレHTML生成のみで、承認記事本文のリッチ自動構成は限定的。
  - 収集は手動トリガー前提（定期実行の内蔵スケジューラは未確認）。

### 2-2. 「効果が出ているLPを集め、自動で公開ページを増やす設定」
- **結論**: **Phase 2の初期版まで実装済み（候補発見の自動化を開始）**。
- 可能な範囲:
  - LPを登録すればAI分析され、公開一覧に自動反映される。
- 現時点の不足:
  - 候補発見は `LP_DISCOVERY_FEEDS` に依存し、探索対象の拡張は運用で調整が必要。
  - 成果推定ロジック（CVR推定等）の客観指標はなく、現状は入力情報+AI推論中心。
  - カテゴリ推定やノイズ除去の精度は今後の改善対象。

## 3. フェーズごとの進め方（順番固定）

> 方針: **Phase 1が完了するまでPhase 2へ進まない。Phase 2が完了するまでPhase 3へ進まない。**

### Phase 1（0〜4週間）: 半自動運用を「省力で回る状態」にする

#### 目的
- 少ない運営工数で、NL配信とLP更新を継続できる運用を作る。

#### 実施タスク
1. RSSソースを20〜40本へ拡張（海外主要 + 日本媒体）。
2. `/api/admin/nl/fetch` を定期実行（Vercel Cron等）し、手動収集依存を減らす。
3. 承認ルールを明文化（例: relevance 70以上は一次採用）。
4. 週次配信の運用テンプレ化（曜日・締切・確認者を固定）。

#### 完了条件（DoD）
- 2週間連続で、**手動作業30分以内/回**で配信できる。
- 週次で最低1号、配信が途切れない。
- 収集エラー率を運用上許容できる範囲（目安10%未満）に維持できる。

#### 次フェーズ移行判断
- 上記DoDを満たしたら Phase 2 へ進行。

---

### Phase 2（1〜2か月）: LP候補の自動発見を追加

#### 目的
- LPを「登録してもらう」から「自動で拾って増やす」へ進化させる。

#### 実施タスク
1. 外部ソース（広告ライブラリ/API/RSS等）からLP候補URLを取得する ingest ジョブを追加。
2. URL正規化・重複排除・到達チェック・カテゴリ推定を自動化。
3. AI分析の閾値ルールを導入（例: 一定スコア以上のみ `active` 公開）。
4. 低品質候補の自動保留（`archived`）と再評価フローを用意。

#### 完了条件（DoD）
- 新規公開LPのうち、**70%以上が自動発見経由**で追加される。
- 重複登録率・無効URL率が運用許容範囲に収まる。
- 手動登録依存を大幅に削減できる。

#### 次フェーズ移行判断
- 自動発見経由での安定供給が確認できたら Phase 3 へ進行。

---

### Phase 3（2〜4か月）: AIネイティブ（ユーザー側もAI活用）へ拡張

#### 目的
- 人間向けUIだけでなく、AIエージェントが使いやすいプロダクトへ拡張し差別化する。

#### 実施タスク
1. LP分析データを機械可読APIで提供（検索・比較・推薦）。
2. AIエージェント向けの定型ユースケースを設計（業界別比較、訴求軸比較、改善候補抽出）。
3. 人間向けには要約・比較・推奨コレクションを強化。
4. SEO流入とLLM経由流入（引用されやすい構造化情報）を両輪で設計。

#### 完了条件（DoD）
- AI利用を前提とした導線/APIが公開され、実利用が発生している。
- 人間流入だけでなく、AI経由流入を計測できる状態になっている。
- 「LPギャラリー + AI意思決定基盤」としてのポジションが明確化される。

## 4. 直近アクション（Phase 2開始後）

## 5. 到達イメージ（あなたの狙いに対する適合）
- 現状コードベースは、**「半自動運用で立ち上げる土台」**として十分。
- 成長の鍵は「段階的に自動化の比率を上げること」で、
  1) Phase 1で運用を省力化
  2) Phase 2で供給（LP追加）を自動化
  3) Phase 3でAIネイティブ優位を確立
  の順が最も失敗しにくい。
- 特にAIネイティブ戦略は、将来的に「人間向けギャラリー」から「AIが参照する意思決定インフラ」へ拡張できるため、差別化余地が大きい。
